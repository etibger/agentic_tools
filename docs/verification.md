# Verification, oracles and shared resources

## Evidence is more than a green process exit

Retain the exact command, working directory, host, candidate, executor, selected suite/test count, result and log. Classify source analysis, executed reproduction, reported result and hypothesis separately.

A zero-test selection is not a pass. Existing test code is not execution. A broad command that discovers ignored duplicate checkout copies does not multiply unique coverage.

Separate product failure from environment failure. If a native check is blocked by permissions, rerun the same command through an authorized mechanism when available. Do not weaken assertions, change exclusions or relocate native caches merely to get green output.

## Calibrate one representative oracle

Before a long interaction matrix, use an owned fixture and confirm the predicate rejects its named false positive.

| Weak predicate seen in the implementation | Stronger observation |
| --- | --- |
| Screen contains seeded “COPY” | Actual copy-mode indicator and transition |
| Clipboard contains one character | Exact intended bytes and target |
| Output contains an echoed command | Distinct executed output, independent of input echo |
| Harness exits successfully | Check outcomes and separate owned-resource cleanup |
| Source and binary look similar | Recorded source/binary identity for the claimed runtime result |

Keep original failures and corrected supplements. A fixture or proof correction is not automatically a product-source defect.

## One native execution owner

Native output, build caches, mutable fixtures and shared services are resources. Name the owner and release condition in every assignment. Read-only reviewers can work concurrently. Separate documentation or platform lanes can execute only when they do not compete for those resources.

Use project-native commands and normal environments. Temporary verification helpers follow the host's scratch policy. Never change global SDKs, accept licenses or install tools without applicable authority.

## State coverage limits precisely

Syntax parsing does not establish native schema validity. Structural parity does not prove semantic documentation accuracy. Buffer tests do not prove every live PTY interaction. One local runtime is not Windows, SSH or cloud qualification.

Performance evidence needs fixed geometry, populated fixtures and matched scenarios. Distinguish supported profiles from an opt-in stress workload. Do not turn unrelated host timing variation into a causal performance claim or invent a release threshold.

## Independent documentation lane

An additional read-only docs verifier can inspect:

- approved requirements and examples;
- semantic prose against production behavior;
- generated source alignment and structural parity;
- syntax versus native validation;
- actual rendered-page quality when tools permit.

The Implementer remains the source writer. Record which checks executed and which claims remain unverified.
