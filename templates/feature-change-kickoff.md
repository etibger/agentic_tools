## Execute

Before investigation, show the shared contract's project structure, initial team, provisional execution team, proposed models/effort and investigation bounds.

1. Inspect the existing behavior, contracts and native commands. Map affected consumers and inherited evidence. Identify which requirements are settled and which need a decision; do not redesign accepted foundations without a concrete reason.
2. Prepare a proportionate Detailed Investigation: behavior, alternatives, data/ownership boundaries, compatibility, failure/recovery, test strategy, acceptance, ordered increments, team/model settings, resources, estimates and stop conditions. Obtain the user's Concept Approval for the exact revision before implementation, unless the user explicitly waives this gate for the task. An existing approval for that exact package needs no duplicate decision. Confirm the actual execution team after approval.
3. Plan one complete user journey around the hardest integration assumption. Probe capacity or platform boundaries early if they can invalidate acceptance. Separate model preparation, integration execution, physical input and final delivery in the remaining-work record.
4. Assign dependency-ordered increments with owners, resource boundaries and objective exit evidence. Keep documentation and preparation parallel where dependencies permit. Do not start more implementation solely to keep agents busy.
5. Implement, run early builds and safe affected tests, then freeze and assess each useful increment under the selected profile. Preserve factual packet independence and findings. Reuse unchanged evidence only with an impact rationale. A small repair need not recreate the entire design review.
6. Perform integrated consumer acceptance on the final coherent candidate. Include compatibility, setup/local use, recovery and required documentation. Close selected delivery and learning actions, and identify ongoing product ownership separately from finite feature completion.

If a new environment or failed feasibility probe changes the promise, retain the actual result and present continue/change/defer options. Mandatory acceptance remains committed until explicitly changed. Additional agents cannot substitute for an unavailable shared executor or unmet prerequisite.
